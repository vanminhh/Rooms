# 21 · Chatbot tư vấn (public room advice)

Decision: D-49 in [00-overview.md](00-overview.md) (owner 26/11/2026, lifts the chatbot part of D-20). Limits: A-29.

A chat bubble on the public pages answers people looking for a room. It only reads public data, the same data the public pages already show (ROOM-05, PUB-01..04). It has no login, stores nothing, and books nothing itself.

| ID | Rule |
|---|---|
| **CHAT-01** | `POST /api/v1/public/chat`, no auth. Body: `messages` = the whole conversation so far, `[{ role: 'user' \| 'assistant', content: string }]`, 1–20 items, alternating, first and last `user`, each visitor (`user`) `content` 1–500 characters after trim, each bot (`assistant`) `content` in the history 1–2000 characters (owner 27/11/2026: a bot reply may be longer than 500, and follow-up questions must still work); optional `roomId` (positive int) = the room page the visitor is on; optional `image` (CHAT-11). Answer `{ data: { reply: string } }`. Anything else → `VALIDATION_FAILED`. Never cached (`Cache-Control: no-store`). |
| **CHAT-02** | The model is Claude Haiku 5.5 (`claude-haiku-5-5`) through the Claude API, key `ANTHROPIC_API_KEY` (filled by the owner). The bot may only call read-only tools backed by the existing public services: search rooms (PUB-01 filters), room detail with the monthly estimate (ROOM-08, A-05), locations, building detail. No tool reads private data, writes, or books. |
| **CHAT-03** | At most 20 chat requests per IP per hour (A-29) → `TOO_MANY_REQUESTS`; the FE then shows the building's phone (or the general message when no room is known). |
| **CHAT-04** | The bot answers only about renting rooms in Rooms buildings, from tool data. It never invents a room, a price or a rule; money is shown as integer đồng (G-01, LOC-05). It replies in English when the visitor writes English, otherwise in Vietnamese (LOC-01 public pages). Off-topic questions get a short polite refusal. |
| **CHAT-05** | Handoff: to visit or rent, the bot gives the room page link `/phong/<id>` (booking a viewing there needs an account, D-28) and the building's contact phone from the public data. It does not take names or phones in the chat. |
| **CHAT-06** | When the key is missing, the provider fails, or the model refuses, the API answers `CHAT_UNAVAILABLE` (503) and the FE shows "Trợ lý đang bận. Vui lòng gọi số điện thoại của tòa nhà hoặc đặt lịch xem phòng." The app still starts without the key. Raw provider errors are never shown. |
| **CHAT-07** | Nothing about the chat is stored on the server (no table, no audit row, no log of message text). The conversation lives in the browser tab and is gone on reload. |
| **CHAT-08** | Suggested questions (owner 27/11/2026): before the first question the panel shows tappable suggestions under the greeting, on the visitor's side (right, like the visitor's own messages); tapping one sends it at once as the visitor's question (same as CHAT-01), and they disappear once the conversation has a question. On a room page (`/phong/<id>`): "Phòng này mỗi tháng hết bao nhiêu?", "Tiền điện nước tính thế nào?", "Đặt lịch xem phòng này thế nào?". Elsewhere: "Phòng dưới 3 triệu?", "Khu vực nào còn phòng?", "Phòng cho nuôi thú cưng?", "Đặt lịch xem phòng thế nào?". English pages show the English translation (LOC-01). |
| **CHAT-09** | Expand (owner 27/11/2026): the panel head has icon buttons like a window title bar: □ expand / ❐ restore (one toggle) and × close (the conversation is kept); their accessible names are the texts "Phóng to" / "Thu nhỏ" / "Đóng trợ lý". Normal: 380 px wide; expanded: 640 px wide and 85% of the screen height, still floating at the bottom right (never a separate page); on a narrow screen both are capped at the screen width minus the 16 px gutters. The conversation is kept when toggling. |
| **CHAT-10** | Room cards (owner 27/11/2026): under a bot reply, each distinct room linked as `/phong/<id>` (first 3, in order) shows a card with the room's first photo (or the no-photo text), room code, building name and rent, loaded from `GET /public/rooms/:id` (PUB-02 data, no extra model call); the card opens the room page. A room that cannot be loaded shows no card; the text link stays. |
| **CHAT-11** | Image (owner 27/11/2026): the visitor may attach one image (JPG, PNG or WebP, file up to 5 MB) to a question; a text question (CHAT-01) is still required [ASSUMPTION]. The browser shrinks it to at most 1568 px on the long edge and re-encodes it as JPEG before sending `image: { mediaType: 'image/jpeg' | 'image/png' | 'image/webp', data: <base64> }` (decoded at most 1.5 MB). The BE adds it to the last visitor message only; later requests carry text history only. The bot uses the image only to understand the request and still answers from tool data (CHAT-04). The JSON body limit is 3 MB for this route only; every other route keeps 100 kB. A wrong type or a file over 5 MB is refused in the browser with a message; nothing about the image is stored or logged (CHAT-07). It counts toward CHAT-03. |
| **CHAT-12** | Stop (owner 27/11/2026): while the bot is answering, the send button becomes a stop button; stopping cancels the request, puts the question (and image) back in the input, adds nothing to the history and shows no error. The BE cancels the model call when the visitor disconnects and does not log it as a failure. |

Error code added: `CHAT_UNAVAILABLE` 503 (see [01-architecture.md](01-architecture.md#error-codes)).
