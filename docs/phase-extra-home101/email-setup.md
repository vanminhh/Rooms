Owner decision, 15/11/2026: complete Resend configuration enables real email in development as well as production. Without it, development/test log email locally; production returns MAIL_UNAVAILABLE. The owner alone edits `.env`. No secret belongs in Git or chat.

## Configuration

1. In [Resend Domains](https://resend.com/domains), add a domain or subdomain you own. Copy the DKIM and SPF DNS records exactly as generated by Resend into your DNS provider, then wait for the domain to be verified. The record names and values depend on your domain; do not copy someone else's records. [Official domain setup](https://resend.com/docs/add-a-domain).
2. In [API Keys](https://resend.com/api-keys), create a key with **Sending access**, scoped to that sending domain. Rooms does not need a full-access key. [Permissions](https://resend.com/docs/api-reference/api-keys/create-api-key).
3. Choose the sender display name and address on the verified domain. The owner puts the following values in `Source/backend/.env`, using the real key and sender address privately:

```dotenv
MAIL_PROVIDER=resend
MAIL_API_KEY=<your-private-Resend-key>
MAIL_FROM="Rooms <no-reply@your-verified-domain>"
```

4. Restart the backend so the module reads the new values. From `D:\Rooms\Source\backend`, the existing project can be started with:

```powershell
node --env-file=.env node_modules/@nestjs/cli/bin/nest.js start --watch
```

The explicit env-file is needed on this checkout because the actual env file is `Source/backend/.env`, while `src/main.ts` also looks for `Source/.env`. Do not create or copy another env file to work around it. `APP_URL` must be the frontend origin the recipient can open; the password-reset link uses that origin.

## Four-message acceptance check

Use only addresses the owner has named for this check. Setting keys does not authorize sending tests to real guests or managers. Keep the mailer faked for automated tests.

| Message | Action | Check |
|---|---|---|
| `emailCode` | Owner signs up a test guest | Six-digit code arrives; verification works; expiry says five minutes. |
| `passwordReset` | Request recovery for that verified test account | Link arrives; it opens the correct Rooms origin and states thirty-minute expiry. |
| `viewingNew` | Test guest books a future available hour | Responsible test manager/Boss receives guest name, phone, email, room, building, date/hour and note in Vietnamese. |
| `viewingConfirmed` | Test staff chooses “Gửi email xác nhận” | Guest receives room, building/address, Hanoi date/hour and public contact in the guest's language. The appointment changes to CONFIRMED only after provider acknowledgement. |

For each row, the owner confirms arrival and checks the spam folder. Resend accepting a request is not proof of inbox delivery. The responsible manager/Boss recipient must be a test recipient agreed with the owner; do not rewrite existing contact settings merely to redirect these emails.

## Templates and retry behavior

The backend reads `settings.email_templates` without inserting or replacing settings. Entries are `{ kind: { vi: { subject, text }, en: { subject, text } } }`; `viewingNew` uses Vietnamese only. Missing or malformed entries use the built-in defaults. Custom wording must retain these placeholders:

| Kind | Required placeholders |
|---|---|
| `emailCode` | `{code}` |
| `passwordReset` | `{url}` |
| `viewingNew` | `{guestName}`, `{guestPhone}`, `{guestEmail}`, `{room}`, `{building}`, `{time}`, `{note}` |
| `viewingConfirmed` | `{room}`, `{building}`, `{address}`, `{time}`, `{contact}` |

An incomplete template falls back to the default; it must not silently send a code-less or link-less email. Each logical email has at most two attempts, each bounded to five seconds, using the same payload and idempotency key. Resend retains idempotency keys for 24 hours. A timeout cannot establish whether the provider accepted a request, and an accepted email cannot be undone if a later database commit fails. [API](https://resend.com/docs/api-reference/emails/send-email) · [Idempotency](https://resend.com/changelog/idempotency-keys).
